Agents write the code. A person decides every question that matters.

Coding agents are fast, and they guess. VibeKit puts one folder in the repo that every agent reads. If it lacks a fact, it writes an ask and stops. Between every stage is a gate a human closes. Nothing advances itself.

What it is for

Spec-driven development that keeps going after the first generation. Spec Kit, and tools like it, get you a spec, a plan, a task list and code. VibeKit is the operating system for what happens next: review, evidence, drift, security, cost, brownfield, and undo.

1

One folder every agent trusts

vibekit/ holds what the app is, what agents may touch, what your words mean, what has been decided, and what is next. Markdown in git. Delete it and the repo still works.

2

A person at every gate

Clarify, architecture, design and plan each wait for a line you write. Nobody but a person sets done or closes a sprint. The tracker on your phone writes the same line.

3

Proof, not claims

vibekit verify writes the commit, the suite and the exit code into the requirement. Red, dirty, another commit, or a skipped test: tested is refused.

Why not just Spec Kit?

GitHub Spec Kit is excellent at the first pass: constitution, specify, plan, tasks, implement, converge. That loop ends when the code exists. VibeKit maps onto those same steps — and then keeps the chain, so a team can still answer “why is this line here?” a month later. Coming from Spec Kit? vibekit project import . --speckit reads the existing files and loses nothing.

The helpers, mapped

Spec Kit’s slash commands and .specify helper scripts get an agent through specify → plan → tasks → implement. VibeKit’s helpers are the same idea with a different centre of gravity: they stop the agent when a person is needed, and they keep going after the code is written.

Spec Kit helpers

/speckit.constitutionGoverning principles
/speckit.specifyWhat to build
/speckit.clarifyResolve ambiguities
/speckit.planStack and architecture
/speckit.tasksBreak the plan down
/speckit.implementExecute the tasks
/speckit.analyzeCross-check the artefacts
/speckit.convergeAppend leftover work

VibeKit helpers

/vibekit.clarifyAsks first. Assumptions get ids.
/vibekit.nextWhatever the current gate allows
/vibekit.buildOne requirement, one branch, evidence
/vibekit.reviewSecond model. A person sets done.
/vibekit.statusWhere everything stands, in words
/vibekit.whyWhy this line of code exists
/vibekit.hotfixProduction is down. Stay small.
/vibekit.new-featureAdd work without a new planning pile

Same commands from a terminal: vibekit action, vibekit sprint run, vibekit tracker <project>. The slash commands are a thin layer over the CLI, so Claude Code, Cursor, Codex and an MCP client are never on different workflows.

Two commands a day

Everything waiting on you, then the current sprint. Or none of this, and the tracker on your phone.

npm install -g ./plugin
cd your-project && vibekit project new

vibekit action          # the inbox, most blocking first
vibekit sprint run      # work the current sprint with several agents
vibekit tracker stock   # QR code; approve gates from your phone
