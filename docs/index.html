The problem I am trying to solve

Specs and agents already write the first version. The mess starts the next morning, when nobody can say what was decided, what was guessed, or why a line is there.

Agents invent policy

They fill the gaps you never wrote.

A coding agent that lacks a fact will pick one. Refunds go to a store credit. Auth is “good enough”. The code compiles. The decision was never yours.

Specs die after generation one

The chain breaks at the first PR.

Constitution, specify, plan, tasks, implement — then the loop ends. Review, evidence, drift, a hotfix, “why is this here?” are left to chat history.

What VibeKit does instead

If it does not know, it asks. If a person has not signed, it does not move.

One folder, vibekit/, is what every agent reads. Unknowns become asks with ids. Assumptions get a blast radius. vibekit verify writes the commit and the exit code into the requirement. A reviewer on a second model writes the verdict. Only a person sets done. Six weeks later, vibekit why src/cancel.js:12 still reaches the paragraph that required it.

Why not just Spec Kit?

Spec Kit gets you to a first version fast, and that's genuinely the hard part starting out. Describe what you want, get a spec, a plan, a task list and working code. Agent OS solves a different problem well — it learns how your team already writes code and feeds the right conventions to the agent, so you stop repeating yourself in every prompt.

Both are good. VibeKit borrows from both and maps onto the same steps. The difference is how far each one takes you. Spec Kit and Agent OS hand you a first version. VibeKit stays for the whole life of the project.

Already using either? vibekit project import . reads what you have. Nothing is lost.

The three things nothing else does

Watch it work. From anywhere.

Agents run for hours. You shouldn't have to sit there. vibekit tracker puts a live board behind a link. Scan the QR code and it's on your phone.

No ids, no step counters.

“Creating a list”, not REQ-007 step 4/5. The file is one tap away if you want it, but you shouldn't need it to know what's going on.

You can act from it, not just watch.

Answer the question blocking a lane. Approve a gate. Reorder the sprint. Every tap is a commit in your repo with your name on it.

Your client can use it too.

Send them the link, they approve from a phone, and you stop being the middleman between an agent and a decision. It's a Cloudflare tunnel behind a login, so the QR code is safe on a wall — scanning it gets you a sign-in page, not your repo.

Several agents. No collisions.

One agent at a time is a waiting game. vibekit sprint run works several pieces at once, across whatever tools you've got.

Mix tools freely. They read the same folder, so a checkpoint written in one is picked up by another — start something in Claude Code, finish it in Cursor, nothing lost. Two lanes is the default. Four is about the limit before merge conflicts eat the gain, and VibeKit tells you rather than letting you find out.

Three rules stop the mess

One job per agent, one branch, one folder each.They physically cannot touch each other's files.
Never two agents on the same entity.Jobs that share one get sequenced instead of racing — which prevents most merge pain before it happens.
A blocked lane blocks only itself.One agent hits a question, the others carry on. Reviews run alongside, not after.

Stop paying premium rates for scaffolding

Your best model doesn't need to write test fixtures.

VibeKit sorts work by what it actually needs and sends each piece to the cheapest thing that does it well.

The workRuns on
Understanding a brief, architecture, planningYour best model
Building a normal featureA mid-tier model
Small fixes, test data, docs, changelogs, routine checksA cheap model
Secret scanning, parsing, matchingYour own machine. Free

Reviews are never cheaper than the work they check. The reviewer always runs a tier above the implementer, on a different model. That rule isn't configurable — it's what makes the cheap tiers safe. Seats you already pay for go first. Metered models only get used for what a seat can't do. On a typical sprint that's around 60% of the work costing you nothing.

The honest version

Spec Kit is free, mature and backed by GitHub. Agent OS is the best thing going for standards. Both have real users today. VibeKit is an alpha built by one person and parts of it are rough.

If you want a clean first version and you're happy driving from there, use Spec Kit. If agents keep ignoring how your team writes code, use Agent OS. They're not mutually exclusive with this — Agent OS standards import straight into VibeKit as skills.

VibeKit is for the project where somebody asks, a year later, why a line is there — and you'd like to answer in a second rather than an afternoon.

Install

Node.js 20+ and Git. The CLI is the same on every tool. Claude Code also gets a plugin; Cursor, Codex and the rest read the pointer files vibekit project new writes. 

npm install -g https://github.com/Pershanthenm/vibekit/releases/download/v0.1.0-alpha/vibekit-0.1.0-alpha.tgz
# or from source:
git clone https://github.com/Pershanthenm/vibekit.git
npm install -g ./vibekit/plugin
vibekit version

Claude Code

The plugin adds slash commands and hooks. The CLI still has to be on PATH.

/plugin marketplace add Pershanthenm/vibekit
/plugin install vibekit
/reload-plugins

cd your-project && vibekit project new

Cursor and Cursor CLI

project new writes .cursorrules. Attach the MCP server so the CLI enforces reads, writes and commands. Same for the Cursor CLI.

cd your-project && vibekit project new

# ~/.cursor/mcp.json — Cursor and `cursor-agent`
{
  "mcpServers": {
    "vibekit": {
      "command": "vibekit",
      "args": ["serve", "--stdio"]
    }
  }
}

Codex

Codex reads AGENTS.md. Point its MCP config at the same stdio server.

cd your-project && vibekit project new

# MCP command
vibekit serve --stdio

Other CLI agents

OpenCode, Aider, or any MCP client: they read AGENTS.md, or they speak JSON-RPC on stdio. Git hooks still apply.

cd your-project && vibekit project new
# or, on a repo you already have:
vibekit project import .

vibekit serve --stdio          # MCP
vibekit serve --stdio --sandbox

Two commands a day

Everything waiting on you, then the current sprint. Or none of this, and the tracker on your phone.

vibekit action          # the inbox, most blocking first
vibekit sprint run      # work the current sprint with several agents
vibekit tracker stock   # QR code; approve gates from your phone
