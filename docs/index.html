The problem I am trying to solve

Specs and agents already write the first version. The mess starts the next morning, when nobody can say what was decided, what was guessed, or why a line is there.

Agents invent policy

They fill the gaps you never wrote.

A coding agent that lacks a fact will pick one. Refunds go to a store credit. Auth is “good enough”. The code compiles. The decision was never yours.

Specs die after generation one

The chain breaks at the first PR.

Constitution, specify, plan, tasks, implement — then the loop ends. Review, evidence, drift, a hotfix, “why is this here?” are left to chat history.

What VibeKit does instead

If it does not know, it asks. If a person has not signed, it does not move.

One folder, vibekit/, is what every agent reads. Unknowns become asks with ids. Assumptions get a blast radius. vibekit verify writes the commit and the exit code into the requirement. A reviewer on a second model writes the verdict. Only a person sets done. Six weeks later, vibekit why src/cancel.js:12 still reaches the paragraph that required it.

What it is for

Spec-driven development that keeps going after the first generation. The operating loop after the spec exists: review, evidence, drift, security, cost, brownfield, and undo.

1

One folder every agent trusts

vibekit/ holds what the app is, what agents may touch, what your words mean, what has been decided, and what is next. Markdown in git. Delete it and the repo still works.

2

A person at every gate

Clarify, architecture, design and plan each wait for a line you write. Nobody but a person sets done or closes a sprint. The tracker on your phone writes the same line.

3

Proof, not claims

vibekit verify writes the commit, the suite and the exit code into the requirement. Red, dirty, another commit, or a skipped test: tested is refused.

Why not just Spec Kit?

GitHub Spec Kit is excellent at the first pass. That loop ends when the code exists. VibeKit maps onto those same steps — and then keeps the chain. Coming from Spec Kit? vibekit project import . --speckit reads the existing files and loses nothing.

The helpers, mapped

Spec Kit’s slash commands walk specify → plan → tasks → implement. VibeKit’s helpers stop the agent when a person is needed, and they keep going after the code is written.

Spec Kit helpers

/speckit.constitutionGoverning principles
/speckit.specifyWhat to build
/speckit.clarifyResolve ambiguities
/speckit.planStack and architecture
/speckit.tasksBreak the plan down
/speckit.implementExecute the tasks
/speckit.analyzeCross-check the artefacts
/speckit.convergeAppend leftover work

VibeKit helpers

/vibekit.clarifyAsks first. Assumptions get ids.
/vibekit.nextWhatever the current gate allows
/vibekit.buildOne requirement, one branch, evidence
/vibekit.reviewSecond model. A person sets done.
/vibekit.statusWhere everything stands, in words
/vibekit.whyWhy this line of code exists
/vibekit.hotfixProduction is down. Stay small.
/vibekit.new-featureAdd work without a new planning pile

Two commands a day

Everything waiting on you, then the current sprint. Or none of this, and the tracker on your phone.

npm install -g https://github.com/Pershanthenm/vibekit/releases/download/v0.1.0-alpha/vibekit-0.1.0-alpha.tgz
cd your-project && vibekit project new

vibekit action          # the inbox, most blocking first
vibekit sprint run      # work the current sprint with several agents
vibekit tracker stock   # QR code; approve gates from your phone
